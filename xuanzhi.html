玄知 · 身心灵 RAG 知识库

2026.05 — 至今 ｜ 独立承接 ｜ Dify + DeepSeek ｜ 原型可运行

一句话：做一个「答不出来时会承认答不出来」的知识库。
这个领域最不缺会说话的东西，最缺可信度——所以我把「可信度」当第一需求，而不是把「能回答」当第一需求。

背景：为什么这件事值得做

身心灵/玄学领域的内容有三个特点：各家说法不一、外行无从判断对错、AI 特别容易一本正经地编。 用户来问的时候，最怕的不是"不知道"，是被一个自信的错误答案误导。所以问题的本质不是"覆盖多少知识"，是"能不能让用户知道哪些话可信、哪些话不该信"。

我做了什么

  1. 划知识边界：把 高频提问梳理后切成 18 个互不重叠的子体系（五行 / 八字 / 紫微 / 人类图 / 生命灵数 / 奇门 / 六爻 / 易经 / 道德经 / 玛雅历 / 七政四余 / 太乙神数 / 盖洛普 + 玄学说明），明确每个体系管什么、不管什么。
  2. 统术语：产出 18 篇主题文档（3.6 万字）+ 1 份术语表，统一同一概念的不同叫法——否则检索时"同一个东西三个名字"，召回必然漂移。
  3. 定可信度标准：确立「资料不足时明说无法确定」的回答口径，并把它落成产品里的边界外拒答行为——不是写在文档里的口号，是用户能实际感受到的差异。
  4. 建评测口径：把「答得好不好」拆成三个可核查的指标——准确率 / 幻觉率 / 拒答率，让迭代有判据而不是靠感觉。
  5. 搭链路 + 治幻觉：用 Dify + DeepSeek 搭 RAG 检索链路，设计 Prompt 模板与 Agent 工作流，做到回答可溯源；逐条收集 badcase 并按类型回灌语料，21 轮迭代每轮都有明确改动对象。

关键取舍（面试官最会问这块）

取舍一：宁可拒答，不要硬答。
常规做法是让模型尽量回答、提高"有问必答率"。我反过来——把"该拒答时拒答"当核心功能。理由：这个领域的错误答案代价远高于"暂时答不上来"。代价是观感上"能力变弱"了，我认为这个交换划算。

取舍二：先定边界，再喂语料。
也可以先把资料全丢进去、让模型自己找相关性。我先划 18 个子体系的边界，是因为边界不清是知识库最先崩的地方——不划界，检索会把不同体系的说法混在一起，越"全"越不可信。

结果

14 子体系主题文档 + 1 份术语表 21 轮迭代，自评分 32 → 40.5 / 60 拒答标准落成产品行为 21 轮迭代，逐轮回灌 badcase

说明：40.5/60 是四视角自评分（用户 / 领域 / 工程 / 合规四个视角我自己各过一遍），不是用户测试分。未公开部署——原型在 Dify 云端可运行，问答表现逐条验证过。

机器评测：自建 20 题评估集（含 4 道边界外题），逐题按三项口径判定——准确率 68.8%、幻觉率 12.5%、边界外拒答 4/4；抓到的 2 条编造（人类图占比、七政四余与五行对应）已定位到原因：语料缺失与跨体系编造。

真人测试：6 名真人用户，每人自己提 10 个问题（共 60 次真实提问），按「这个回答能不能直接用」判定——可用率 85%（46/54）、边界外拒答 6/6、有用性 4.3 / 5。局限：样本 6 人、非随机抽样；判定由测试者主观给出，不是双人交叉。

如果重做，我会改什么

  • 把真人反馈接进迭代闭环。6 人测试已经拿到反馈，但回访链没建起来——测完一轮就停了。下一步是把「测试 → 改 → 再测」固化成固定动作，而不是一次性活动。
  • 把评测做成脚本。现在是人工逐条判，题量一大就不可持续；应该把"同一批题跑多版本、自动出一致性对比"做成工具。
