简历 3 页压到 1 页：根因是缺 @page，不是内容太多

2026-09 ｜ 打印排版 / CSS ｜ 阅读约 6 分钟

一句话结论：页数超标时，先怀疑样式，别先删内容。 没有 @page 规则时，浏览器按默认边距排版，屏幕样式里那些 max-width 和大 padding 在打印场景下是纯粹的浪费—— 把版面还回来，正文反而能写得更长。

问题

简历用 Markdown 写、转成 PDF 投递，要求一页 A4。转出来是 3 页。

第一反应是「内容太多了，删吧」。但删之前先问了一句：到底是内容装不下，还是版面被浪费了？ 这两个原因看起来症状一样，处理方式完全相反——如果是版面问题，删内容等于白删，删完还难看。

先量，再改

打开生成的 HTML 看样式，两个数字很扎眼：

  • 整份样式表里 @page 出现 0 次。
  • 带着 pandoc 默认样式：max-width: 36em、padding: 50px。

这两个数字就把结论定死了。分两次说清楚：

① max-width: 36em 是屏幕样式的遗留物。 它把正文限制在约 36 个字符宽（中文更少），在屏幕上是为了防止一行太长不好读。 但打印时纸张宽度是固定的 A4，这个限制不会让纸变窄——它只会让文字挤在纸中间一窄条， 两侧留下大片空白。同样的内容，占用更多纵向空间。

② 没有 @page，就没有页面的规格和边距控制。 浏览器会退回默认边距（通常在 10–13mm 上下），而你对此毫无控制权。 换句话说：这一版的页边距、纸张尺寸、缩放，全都不是你决定的。

结论：不是内容多，是版面没被管过。

改法

在样式表末尾加一段打印专用规则（顺序很重要，放在最后覆盖前面的）：

/* 1. 页面规格：由你决定纸张与页边距，而不是浏览器默认 */
@page {
  size: A4;
  margin: 9mm 11mm;
}

/* 2. 清掉屏幕样式对打印的干扰 */
html, body {
  max-width: none;   /* 别把正文挤成窄条 */
  padding: 0;
  margin: 0;
}

/* 3. 打印专用字号与行距：一页塞得下、又不至于难读 */
body  { font-size: 10pt; line-height: 1.30; }
h1    { font-size: 15pt; margin: 0 0 4pt; }
h2    { font-size: 11.5pt; margin: 10pt 0 3pt; }
p, li { margin: 2pt 0; }

三段的职责分别是：定纸张、清干扰、调密度。缺任何一段都压不下来。

结果

3 页 → 1 页 正文字数反而增加 字号 10pt（可读下限）

压完之后正文比改之前更长——因为省下来的是版面，不是内容。 这次改动一个字的经历都没删，反而补进了更多细节。这正好反证了最初那个判断是错的。

可复用的检查清单

遇到「HTML/Markdown → PDF 页数超标」，按这个顺序查，比删内容快得多：

  1. 先看 @page 在不在。不在就先加上——这一步经常直接解决问题。
  2. 看有没有 max-width 和容器 padding。打印时把它们归零。
  3. 看有没有 margin 双重叠加。容器的 margin 和 @page 的 margin 会相加。
  4. 再看字号和行距。正文下限约 10pt，行距 1.25–1.35；再小就影响阅读了。
  5. 最后才考虑删内容。而且删之前先确认：删掉的确实是冗余，不是可用信息。

什么时候不适用

  • 分页由内容语义决定时不要硬压。书籍、报告、论文的页数本就该由内容决定，强行压成一页是把信息挤没了。
  • 已经明确需要多页时，这段规则只该用来控制边距，不要用来缩字号。
  • 纯屏幕用途不需要这套规则——它是打印专用层，加在样式表末尾即可，不影响屏幕显示。

一句话记住：屏幕样式管的是「读起来舒服」，打印样式管的是「纸上的物理占用」。 把两者混在一起用，就会出现「内容不多但页数很多」这种看着像玄学的问题。 一旦分开，它就只是几个数字。
